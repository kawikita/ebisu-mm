# バージョニング

## 概要

- バージョン番号のルールについて説明します。

## ルール

### 基本ルール

- バージョンを"."(ドット・ピリオド)で4つに区切ります。
- 区分けの詳細は以下の通りです。
    - 表記: Major.Minor.Release.Build
    - Major: メジャーバージョン
    - Minor: マイナーバージョン
    - Release: リリースバージョン
    - Build: ビルド番号

### 初期開発バージョン

- メジャーバージョン: 0固定
- マイナーバージョン: 1以上。
    - 機能を追加するごとにインクリメントします。
- リリースバージョン: 任意
- ビルド番号: 任意

### リリース以降のバージョン

- メジャーバージョン: 1以上
    - アーキテクチャやebisu_api全体に関わる変更があった場合にインクリメントします。
    - または、マイナーバージョンが20以上になった任意のタイミングでインクリメントします。
- マイナーバージョン: 0以上。
    - 機能を追加するごとにインクリメントします。
    - メジャーバージョンがインクリメントしたら0に戻します。
- リリースバージョン: 1以上
    - 0は開発用ビルドで使用します。
    - セキュリティパッチなどはリリースバージョンをインクリメントします。
- ビルド番号: 0以上
    - デプロイのビルド時にインクリメントします。

## ビルド番号の自動インクリメントとリセット

- 本プロジェクトでは、ビルドごとにビルド番号（バージョンの4つ目の区切り）が自動的にインクリメントされます。
- 仕組みは `build.rs` により、`build_number.rs` というファイルにビルド番号が記録・更新されます。
- 通常の `cargo build` や `cargo run` では、前回のビルド番号に+1した値が自動でセットされます。
- ビルド番号を任意の値にリセットしたい場合は、以下のように環境変数 `RESET_BUILD_NUMBER` を指定してビルドしてください。

```
RESET_BUILD_NUMBER=0 cargo build
```

- これにより、ビルド番号が指定した値（例: 0）にリセットされます。
- バージョン表示コマンド（`cargo run -- version` など）で、`0.2.0.{BUILD_NUMBER}` のように4区切りで出力されます。

- この仕組みにより、CI/CDや手動ビルド時に一意なバージョン番号を自動管理できます。
